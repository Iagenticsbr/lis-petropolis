1 Resumo e decisões propostas

O LIS monitora fontes públicas da web sobre o portfólio de bebidas do Grupo e entrega, a cada ciclo, análises de tendência (mínimas e máximas) e insights. Cada insight pode ser rastreado até o conteúdo que o originou.

Arquitetura

Três trilhas de coleta (scraper próprio em HTTP, scraper próprio com navegador e Apify) entregam o mesmo contrato, RawItem. Tudo roda em containers com infraestrutura em Terraform. Por isso o destino de hospedagem continua em aberto sem bloquear o desenvolvimento.

Dados

Quatro schemas no Postgres (core, analytics, gov, bi) mais uma zona bruta em armazenamento de objetos. Rótulos e insights só são acrescentados, nunca sobrescritos, e cada linha guarda a versão do modelo que a produziu.

Análise

Seis níveis, de N0 (item rotulado) a N5 (relatório). O código calcula tudo o que é número, o Jev rotula em volume e o Claude escreve a partir do N3 (no N0, só dá segunda opinião quando o Jev tem pouca confiança). Toda frase cita evidências, e validadores em código recusam texto que traz número sem origem.

2 Arquitetura de software

Coleta, normalização, classificação, agregação, síntese e entrega, com três fornecedores externos nos pontos em que o texto sai do nosso ambiente.

2.1 Princípios

Contrato único na entradaTodo coletor entrega RawItem. Trocar uma fonte de Apify para scraper próprio só muda o módulo de coleta.
Números em código, texto no LLMContagens, picos e vales saem de SQL e estatística. O Claude escreve sobre números que já existem.
Toda afirmação cita evidênciaDo relatório até o payload bruto, cada peça aponta para as que a sustentam.
Versões fixasModelo, prompt e taxonomia têm versão gravada em cada resultado. Nada de “latest” em produção.
PortabilidadeContainers e Terraform. Nenhum serviço proprietário de nuvem no caminho crítico.
Dado pessoal mínimoAutor em hash, texto mínimo para terceiros, agregados para o Claude.
Falhar à vistaCanário, cobertura por fonte e fila de revisão no lugar de erro silencioso.

2.2 Para onde vai cada fonte

A decisão é por fonte e fica registrada em sources/catalog.yaml, junto com o status jurídico. Quatro perguntas, nesta ordem: é público e sem login? Os termos e o robots.txt permitem, ou o jurídico liberou? Há defesa ativa contra robôs? O conteúdo precisa de JavaScript?

TrilhaQuando usarFerramentaAtenção
Própria, HTTPPúblico, sem login, termos permitem, sem defesa ativa, HTML estático, feed ou API.httpx e Scrapy; API oficial quando existir.O custo é manutenção: o site muda e o seletor quebra.
Própria, navegadorMesmas condições, mas o conteúdo só aparece com JavaScript.Playwright.Um guia de mercado estima de 2x a 5x mais CPU e memória que HTTP.

Exemplo de entrada no catálogo

- id: portal-exemplo
  nome: Portal de notícias de bebidas (exemplo)
  trilha: own_http            # own_http | own_js | apify | fora_mvp
  cadencia: 6h
  status_juridico: liberado   # liberado | pendente | negado
  robots_ok: true

Cada entrada vira uma linha em core.source na implantação. Mudar a trilha de uma fonte é editar este arquivo e trocar o módulo de coleta, sem tocar no restante do pipeline.

2.4 Classificador e roteamento

O Jev classifica cada item; o Claude pequeno só dá uma segunda opinião quando a confiança fica abaixo do limiar τ. A Figura 2, na página seguinte, mostra o roteamento. A tabela abaixo resume o que as fontes consultadas dizem sobre o Jev (Anexo D); preço, latência e limites são do fornecedor e podem mudar.

O que se sabe do Jev

TemaO que as fontes dizem
O que éModelo de decisão da TypeSafe: lê um estado (texto ou JSON) e responde perguntas fechadas com probabilidade. Não gera texto.
ChamadaPOST /v1/systemone com state, model e questions. SDK em Python (typesafe-sdk) e em JavaScript.
Perguntasnoul (sim ou não, devolve a probabilidade de sim), choice (uma opção entre até 255, com probabilidades e confiança) e score (posição numa escala ordenada, com confiança).
Versõesjev-latest muda quando sai versão nova; jev-1.13.0 é um exemplo de versão fixa. Usar versão fixa para os limiares continuarem valendo.
Limites64 mil tokens por requisição, sendo até 32 mil para o estado mais a maior pergunta. Só texto. Sem ajuste fino por cliente.
IdiomaO treino principal é em inglês, segundo a TypeSafe. Português não foi testado nas fontes consultadas.
PreçoUS$ 0,042 por milhão de tokens de entrada, com saída gratuita (valor divulgado pelo fornecedor).
LatênciaDe 70 a 500 ms segundo a TypeSafe. Um teste independente mediu de 197 a 531 ms com três perguntas por chamada, a partir de Toronto.
AvisosNão explica o raciocínio. A mesma entrada pode variar levemente. Contas e datas devem ficar no código. “Sem alucinação” quer dizer não inventar opções fora do esquema, não acertar sempre.
PrivacidadeRetenção e uso dos dados não aparecem nas páginas consultadas. Pedir os termos à TypeSafe antes de enviar dado do Grupo.

2.5 Repositório e esteira de desenvolvimento

lis/
├─ sources/catalog.yaml     # fonte, trilha, status jurídico
├─ src/lis/
│  ├─ contracts/            # RawItem, Item, Label (pydantic)
│  ├─ collectors/
│  │  ├─ own/               # um módulo por fonte
│  │  └─ apify/             # um adaptador por actor
│  ├─ normalize/            # idioma, dedupe, autor em hash
│  ├─ classify/             # Classifier + adaptadores jev, claude
│  ├─ aggregate/            # séries, picos e vales, exemplos
│  ├─ synthesize/           # prompts, validadores, níveis N3 a N5
│  ├─ deliver/              # relatório e views SQL
│  └─ pipeline/             # orquestração (Dagster ou Prefect)
├─ evals/                   # conjunto de referência, F1, Jev x Claude
├─ tests/                   # HTML gravado e testes de contrato
└─ infra/                   # Terraform, Dockerfiles, compose

Cada fonte nova é um módulo em collectors/own ou um adaptador em collectors/apify, com o HTML gravado em tests/. Nenhum módulo conhece a nuvem: o que muda por ambiente vem de variáveis e do Terraform.

O canário diário é o que torna viável ter scrapers próprios. Ele avisa quando um site mudou antes de a taxa de coleta cair abaixo dos 95% do M1.

O gate de F1 impede que uma troca de prompt, de versão do Jev ou de modelo piore a classificação sem ninguém ver. Os prompts dos níveis N3 a N5 ficam em synthesize/ como arquivos versionados, e o hash de cada um é gravado em analytics.insight.
